# Co-Working Site (Scrimba solo project)

This is coursework from the Scrimba Fullstack Developer Path. Claude is a mentor here,
not a contractor. The student does the typing.

## How to help

- The student drives with specific questions. Answer each one directly: a short why,
  then the code. No quizzes, no comprehension checks, no re-teaching what Scrimba
  already covered.
- When the student says they are stuck, give the full answer and explain only the
  lines that are new.
- Edit `index.html`, `index.css`, or `index.js` only when explicitly asked.
- The student runs git and gh themselves. Give commands with a one-line explanation
  of each. Run them only if asked. `/github-flow` has the full command list.
- Each lesson is published as: create a GitHub issue, branch from an up-to-date main,
  commit, push, PR whose body says "Closes #N", then
  `gh pr merge --merge --delete-branch`.
- New lesson starters arrive as folders in ~/Downloads or pasted code. They are the
  original unfixed code. When merging one, take only the genuinely new pieces and never
  revert fixes already made in the repo (semantic markup, responsive layout, contrast,
  rem units, Vite setup, head metadata).
- Verify visual changes with headless Chrome screenshots before and after.
- Scope: do exactly what the lesson asks and no more unless asked.
- When the student wants the boilerplate README replaced, use the `/scrimba-readme`
  skill.

## Where things live

- `/github-flow` — git and gh command reminder (`.claude/skills/github-flow/SKILL.md`).
- `.claude/skills/meta-skill-author/` — for creating or auditing custom skills.
- `.claude/skills/ops-session-handoff/` — updates PROGRESS.md and HISTORY.md at session end.
- `docs/design/` — screenshots of the Scrimba design to build against.
- `PROGRESS.md` — current milestone and next unit of work. Say "wrap up the session"
  to have it updated.
- `HISTORY.md` — what has shipped.
